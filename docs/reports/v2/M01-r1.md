## 3. Queue-hold and auth behavior

`V2QueuedRevision.state` is now `PENDING | HELD | BLOCKED_AUTH | ACKNOWLEDGED`. The queue preserves the exact envelope bytes in every hold.

| Condition | State | Reason | Network effect |
| --- | --- | --- | --- |
| No provisioned bearer credential | `BLOCKED_AUTH` | `auth_missing` | No request is sent |
| `GET /capabilities` or `POST /observations` returns 401 (valid or bodyless) | `BLOCKED_AUTH` | `blocked_auth` | Pause |
| 403 | `HELD` | server code or `forbidden` | Operation pause |
| Capabilities missing/invalid, old batch limit, stale registry, disabled/unknown gate shape, malformed or unavailable | `HELD` | `unsupported_or_unavailable_capabilities` | Observation never attempted |
| Server advertises a content gate as not enabled (`activity`, `email`, `location`) | `HELD` | `capabilities.featureGates` | Observation never attempted |
| 422 `unsupported_contract` | `HELD` | `unsupported_contract` | — |
| 409 `identity_conflict`, 422 `version_conflict`, 429, 503, offline, malformed 2xx, mismatched receipt | `PENDING` | server code or `invalid_or_missing_acknowledgement` | Retry allowed |
| 200/201 receipt matching `deliveryId`, `producerRevisionId` and `contentFingerprint` | `ACKNOWLEDGED` | — | Removed from queue by caller |

Regression coverage in `contracts:verify` includes unsupported capabilities (old batch limit, `email: true`, stale currency registry, missing fields), gate holds for activity and email envelopes with **no** observation POST, missing-token no-network hold, bodyless 401, 403, 409/422/429/503, unsupported contract, malformed 2xx, mismatched receipt, offline capabilities, and ordered batch receipt checks.

## 4. Auth provisioning

`lib/api.ts` no longer constructs the transport with an unset token. The call site supplies a provider that reads the out-of-band device credential from secure storage on each request:

- Storage key: `brainia_mobile.v2AccessToken` (exported as `V2_ACCESS_TOKEN_KEY`).
- `config.accessToken` still wins when supplied.
- No secret is hardcoded, logged, or written into the bundle.
- The approved connector callback (`security: []`) is the only operation allowed to omit the bearer header; every other published operation fails closed without a token.

**Follow-up (M02 / G-V2-AUTH):** nothing in this repository writes `brainia_mobile.v2AccessToken` yet. Enrollment, rotation, revocation, expiry and logout are credential-lifecycle work reserved to M02 and were not implemented here. Until enrollment writes that key, v2 delivery correctly holds as `BLOCKED_AUTH` rather than sending unauthenticated traffic.
