## Credential and consent behavior

- Expo SecureStore is the single Android credential store for `brainia_mobile.apiKey` and `brainia_mobile.clientId`. JS continues using Expo's storage API; native capture and diagnostics read its AES/GCM envelope with the same non-exportable AndroidKeystore key. Native configuration no longer receives or writes credential copies. The native reader is deliberately tied to installed expo-secure-store 57's default `key_v1` envelope; verify it when upgrading that dependency.
- Migration reads the existing encrypted JS session first, including an intentionally empty credential. If absent, it imports the legacy native preference value. It rewrites older Expo envelopes using the installed format, verifies the value through the native reader, then synchronously removes the legacy preference. This ordering avoids deleting the only usable credential before secure persistence succeeds.
- Failed migration/decryption shows a visible Spanish reauthentication alert directing the user to Settings > Advanced. Automatic settings persistence is blocked for that failed credential until the user intentionally edits its input. A failed write or verification retains the legacy value for retry rather than silently dropping the session; successful migration leaves no plaintext preference copy. Complete migration requires launching the upgraded app; legacy-only sessions cannot be migrated by the background listener before JS hydration.
- Rapid Android credential edits are serialized through secure write and native verification so an earlier write cannot verify against or overwrite a later value. Deletion waits for pending writes before clearing the secure and legacy copies.
- Native capture and diagnostics do not read plaintext preference credentials. Capture rejection bodies and diagnostic rejection bodies/exception messages are no longer logged or persisted. Native exception logs omit throwable details, and configuration clears the previously persisted diagnostic upload-error field.
- Android backup is disabled. Explicit legacy backup and Android 12+ cloud/device-transfer XML rules exclude all app data domains, including SecureStore, native preferences, device-protected preferences, files and databases. The compiled merged manifest was inspected and retains `allowBackup=false` plus both custom rule references.
- Consent is `unconfigured` when the package-selection preference is absent, `empty` when it exists with no packages, and `selected` otherwise. Both unconfigured and explicitly empty selections capture zero notifications. There is no finance-app fallback. Exact selected-package matching governs posted and reconciled notifications; forwarding rechecks the selection when queued work starts.
- Settings explains unconfigured and paused capture, provides an explicit “Pausar toda la captura” action, awaits successful native selection persistence before updating switches, and shows a save failure instead of presenting an unsaved selection as effective. Existing Switch accessibility labels/roles remain in use.
